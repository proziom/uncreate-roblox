# Uncreate-roblox

Свой **Team Create** для Roblox Studio. Сервер проекта работает у вас (на ПК или VPS), Studio подключается к нему плагином.
Открыли пустой Baseplate, даже несохранённый, нажали **Connect** — и у вас весь проект, а все правки всех участников видны в реальном времени.

Сервер — одна программа на C без зависимостей. Плагин — один файл.

> [!IMPORTANT]
> Скачивайте только со страницы [**Releases**](../../releases) этого репозитория.
> Весь сервер — это один файл [`server/uncreate-server.c`](server/uncreate-server.c), его можно прочитать и собрать самому.

> [!WARNING]
> Антивирус может ругаться на `uncreate-server.exe`: это неподписанная программа, которая открывает сетевой порт.
> Если не доверяете готовой сборке — соберите сервер из исходника (раздел «Сборка и тесты» ниже).

> [!CAUTION]
> Всегда задавайте **ключ** (пароль сервера). Без ключа к вашему проекту сможет подключиться любой, кто знает адрес.

## ⚙️ Использование

> [!NOTE]
> Код в самом репозитории не собран — кнопка «Code → Download ZIP» даст исходники без программы сервера. Для работы нужен готовый архив `Uncreate-roblox-<версия>.zip` со страницы Releases.

1. Скачайте архив `Uncreate-roblox-<версия>.zip` из [**Releases**](../../releases) и распакуйте его в любую папку.
2. **Сервер.** Откройте `start-server.bat` блокнотом и поменяйте три строки: `PROJECT` — название проекта (латиницей, без пробелов), `KEY` — пароль, `PORT` — порт. Сохраните и запустите файл двойным кликом.
   - Откроется чёрное окно — это и есть сервер. Не закрывайте его, пока работаете.
   - Если Windows спросит про брандмауэр — разрешите.
   - Проект хранится в папке с его названием рядом с батником (например, `MyGame`). Разные названия — разные проекты.
   - В окне сервер сразу пишет адреса, по которым к нему можно подключиться.
3. **Плагин.** Скопируйте **один файл** `Uncreate-roblox.rbxmx` в папку плагинов Studio: вкладка **Plugins** → **Plugins Folder**. Перезапустите Studio.
4. **Первый участник** нажимает **Uncreate**, вводит адрес сервера, ключ и имя, затем **Connect**.
   - Studio спросит разрешение на HTTP-запросы — разрешите.
   - Сервер пуст, поэтому плагин предложит сделать **текущий плейс** проектом. Так переносится существующая игра: откройте её `.rbxl` и подключитесь.
5. **Остальные** открывают пустой Baseplate и подключаются так же. Плагин предупредит, что содержимое плейса будет **заменено** проектом с сервера.

Адрес сервера: `127.0.0.1:7878` на своём компьютере, `IP:7878` для друзей (раздел «Как подключить друзей» ниже).

## ℹ️ Файлы

- `start-server.bat` — запуск сервера на Windows. Внутри задаются название проекта, ключ и порт.
- `bin/uncreate-server.exe` — сервер для Windows. Параметры: `--port 7878`, `--key пароль`, `--data папка`, `--bind 0.0.0.0`.
- `bin/uncreate-server-linux-x86_64` — сервер для Linux (например, для VPS).
- `Uncreate-roblox.rbxmx` — плагин для Studio.
- `MyGame/` (по названию проекта) — появляется после первого запуска. Здесь лежит весь проект: снимок и журнал изменений.

## 🌐 Как подключить друзей

Плагину друга нужно достучаться до порта сервера (по умолчанию `7878`) на вашем компьютере. Radmin VPN **не обязателен** — это лишь один из способов. При запуске сервер сам пишет подходящие адреса:

```
  this PC:      127.0.0.1:7878
  other PCs:
    192.168.1.5:7878   (local network / VPN)
    26.14.88.120:7878   (Radmin VPN)
```

Выберите вариант:

- **Одна домашняя сеть (один роутер)** — ничего ставить не нужно. Друг вводит адрес вида `192.168.x.x:7878`.
- **Виртуальная локальная сеть** — Radmin VPN, ZeroTier или Tailscale. Вы и друг ставите программу и входите в одну сеть, друг вводит ваш адрес в этой сети (у Radmin VPN он начинается с `26.`). Порты пробрасывать не нужно — это самый простой способ через интернет.
- **Проброс порта** `7878/TCP` на роутере к вашему компьютеру. Друг вводит ваш внешний IP. Работает не у всех провайдеров.
- **VPS** — сервер работает круглосуточно и не зависит от вашего ПК: `./uncreate-server-linux-x86_64 --key пароль --data MyGame`.

При первом запуске Windows спросит про брандмауэр — разрешите доступ, иначе друзья не подключатся.

Трафик идёт по HTTP без шифрования. Через открытый интернет лучше работать в виртуальной сети или поставить перед сервером прокси с HTTPS (Caddy, nginx) и вводить в плагине адрес `https://…`.

## ✅ Что синхронизируется

Workspace (кроме Terrain), Lighting, MaterialService, ReplicatedFirst, ReplicatedStorage, ServerScriptService, ServerStorage, StarterGui, StarterPack, StarterPlayer (вместе со StarterPlayerScripts и StarterCharacterScripts), SoundService, Teams.

- Создание, удаление, перемещение, копирование, вырезать/вставить, переименование.
- Свойства всех распространённых типов: Vector3, CFrame, Color3, UDim2, Enum, NumberSequence, Font, ссылки на объекты и т.д.
- Атрибуты и теги (CollectionService): добавление и снятие тега у любого объекта.
- Код скриптов прямо во время набора (не чаще раза в 0.4 с на скрипт).
- Основные свойства сервисов: освещение, гравитация, настройки StarterPlayer.
- **Присутствие, как в Team Create:** в окне плагина видно, кто в сети, а во вьюпорте летают головы коллег там, где их камера, с именем над ними. Головы видны только у вас на экране и в плейс не попадают.

Если двое одновременно меняют **одно и то же свойство** одного объекта, остаётся значение того, чей пакет сервер получил позже, — у всех одинаковое. Разные свойства одного объекта не конфликтуют.

## ⚠️ Ограничения

- **Terrain** пока не синхронизируется.
- **Скрипты** не редактируются совместно посимвольно: если двое одновременно печатают в одном скрипте, сохранится версия того, кто отправил позже.
- Каждый объект получает атрибут `UncreateId` — это его постоянный идентификатор. Не удаляйте его; на игру он не влияет.
- Отмена (Ctrl+Z) работает как обычно, и отменённое действие тоже уходит остальным.
- Сама Roblox Studio по-прежнему требует входа в аккаунт. Uncreate заменяет только Team Create.

## ☑️ Частые вопросы и проблемы

### Кнопка Uncreate не появилась
Проверьте, что в папке плагинов лежит именно файл `Uncreate-roblox.rbxmx`, а не папка с ним. Перезапустите Studio. Ошибки плагина видны в окне **Output** (View → Output).

### «server … did not answer»
- Окно сервера должно быть открыто.
- Адрес вводится в виде `IP:порт`, например `127.0.0.1:7878`.
- Ключ в плагине должен совпадать с `KEY` в `start-server.bat`.
- Если Studio спрашивала разрешение на HTTP и вы отказали — разрешите в **Plugins** → **Manage Plugins** → Uncreate.

### Друг не может подключиться, а у меня всё работает
У вас работает `127.0.0.1`, а другу нужен ваш внешний адрес или адрес в виртуальной сети. Проверьте брандмауэр Windows и проброс порта (раздел «Как подключить друзей» выше).

### В журнале «… can't be synced; skipping it»
Это свойство нельзя передать (например, оно ссылается на объект вне синхронизируемых сервисов). Сообщение показывается один раз и ни на что больше не влияет.

### Как начать проект заново
Остановите сервер и удалите папку проекта (например, `MyGame`) — или просто поменяйте `PROJECT` в батнике на новое название. Следующий подключившийся станет хостом.

### Как обновить Uncreate
Замените `bin/`, `start-server.bat` и `Uncreate-roblox.rbxmx` новыми файлами. Папку проекта не трогайте — в ней весь проект.

### Не нашли своей проблемы
Откройте [Issue](../../issues) и приложите текст из журнала в окне плагина и из окна сервера.

## 🛠️ Сборка и тесты

Сервер собирается любым компилятором C11, зависимостей нет:

```sh
# Linux / macOS
cc -O2 -std=c11 -o uncreate-server server/uncreate-server.c
# Windows (MinGW / MSYS2)
gcc -O2 -std=c11 -o uncreate-server.exe server/uncreate-server.c -lws2_32
```

Плагин собирается из `plugin/src/` в один файл:

```sh
python3 plugin/build.py      # → plugin/Uncreate-roblox.rbxmx
```

Тесты:

- `python3 server/test_protocol.py ./uncreate-server` — протокол сервера: вход, журнал, long-poll, снимки, присутствие, перезапуск.
- `plugin/test/run_e2e.sh` — четыре «Studio» на модели движка под [Lune](https://github.com/lune-org/lune) работают через настоящий сервер и должны сойтись.

## 🧩 Как это устроено

Проект на сервере — это **снимок** (блоки rbxm, которые Studio сама сериализует через `SerializationService`, плюс сжатие zstd) и **журнал** пакетов изменений. Сервер только нумерует, хранит и раздаёт данные — Roblox-данные он не разбирает.

- **Вход** — бинарным снимком: тысячи объектов приходят за несколько запросов.
- **Дальше** — только изменения. Плагин склеивает все правки за 0.15 с в один пакет: перетаскивание 3000 деталей — это один пакет.
- **Доставка** — long-poll: сервер отвечает сразу, как только кто-то прислал пакет.
- Когда журнал разрастается, сервер просит одного из участников загрузить свежий снимок и обрезает журнал.

<details>
<summary>Протокол</summary>

Пакет — JSON-массив операций, сервер присваивает ему номер ревизии:

| op | поля | смысл |
|---|---|---|
| `new` | `id, p, b, z` | поддерево объектов (rbxm в base64, `z=1` — zstd) в родителя `p` |
| `set` | `id, k, v` | свойство `k` = `v`; `k="Parent"` — перемещение |
| `attr` | `id, k, v` | атрибут |
| `tag` | `id, k, v` | тег `k` есть (`v=true`) или снят (`false`) |
| `del` | `id` | удалить объект вместе с потомками |

HTTP API (ключ в заголовке `X-Key`): `POST /hello`, `GET /poll`, `POST /ops`, `POST /presence`, `GET /snap/manifest`, `GET /snap/chunk`, `POST /snap/begin|part|commit`, `POST /import`, `GET /status`.

Загрузить `.rbxm` в проект без Studio:

```sh
curl -H "X-Key: пароль" --data-binary @map.rbxm "http://IP:7878/import?into=Workspace"
```

</details>
